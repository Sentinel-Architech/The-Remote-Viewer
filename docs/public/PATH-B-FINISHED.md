## Purpose

This document defines the minimum verifiable standard that an independent builder must meet to be recognized as a **Founding Member** under Path B and to receive the option to operate the Integrity Verifier role.

Recognition is earned by work, not invitation. No free packs are granted. Catalog items remain paid per item.

---

## FINISHED Criteria (Minimum)

An independent builder is considered **FINISHED** when they can demonstrate, on their own device under their own control, **all** of the following:

1. **Optical air-gap end-to-end**  
   age encrypt → Robust Soliton LT (TRVL) → peel → decrypt, with private keys never leaving the device.

2. **Local age identity**  
   Created and used for a successful Path B USDC-memo → TRVL delivery cycle.

3. **Integrity Verifier**  
   Successfully run against the builder’s own contribution ledger + sales.log, producing overall_ok=1 and a recorded contribution weight.

4. **Hydra multi-head defense**  
   integrity-pulse (or equivalent) returns PASS on the builder’s installation.

5. **Local operator surface**  
   Local operator UI (`127.0.0.1`) or equivalent mobile Hub / Viewer Profile surface is operational and can display the above attestations.

---

## Proof Format

Proof must be an optical-transferable or file-based signed attestation package that the originator can independently re-verify without requiring continuous network access or platform custody.

The attestation is bound to the builder’s sovereign identity path.  
Destroy = Restart extinguishes Founding Member status and the Integrity Verifier option along with everything else.

---

## Explicit Non-Claims

- Path B recognition does **not** waive or refund any catalog pack prices.  
- No free packs, no yield, no custody, no permanent privilege.  
- Multiple machines under the same identity path do not multiply weight.

---

## Next Steps After Recognition

Upon verified completion the originator returns a signed Founding Member attestation.  
The builder may then activate the Integrity Verifier role under the constraints permanently locked in `docs/locked/17-Validator-Node-First-Role.md`.
